# Qt 6.11 QML Ahead-Of-Time (AOT) & Compiler Skill Rules Audit

**Date:** 2026-08-18
**Target Qt Version:** Qt 6.11 (Qt 6.11.2)
**Primary Sources:** Official Qt 6.11 Documentation (`doc.qt.io/qt-6/`), Qt QML compiler internals, and `all_aotstats` build analysis.

---

## Executive Summary

An audit of the rules in `qt-quick-compiler/SKILL.md` was conducted against the **Qt 6.11 documentation** and active build telemetry (`.aotstats` files generated by `qmlcachegen`).

- **Rules 1, 4, 5, 6, 7, and 8 are 100% accurate and aligned with Qt 6.11 best practices.**
- **Rule 3 is valid**, but can be expanded to include Qt 6 typed sequence properties (`list<string>`, `list<int>`).
- **Rule 2 contains a critical bug in its recommended QML workaround**:
  1. `Qt.alpha()` does not exist in standard `QtQuick`/`QtQml` (it only existed in experimental labs modules).
  2. Calling `Qt.alpha()`, `Qt.rgba()`, or `Qt.tint()` inside a QML JS function still causes that QML function to fail AOT compilation (`codegenResult: 2` bytecode fallback). To achieve 100% C++ AOT compilation, dynamic color manipulation must be implemented in a **C++ helper/singleton** exposed to QML, or use static hex color literals with alpha (e.g. `"#80ffffff"`).
- **New Qt 6.5–6.11 Pragmas and Built-in Tools** (`all_aotstats` CMake target, `pragma ValueTypeBehavior: Addressable, Assertable`, `pragma FunctionSignatureBehavior: Enforced`, `pragma ListPropertyAssignBehavior`) should be incorporated into the skill.

## Detailed Rule-by-Rule Audit

### 1. Compiler Architecture Quick Reference
- **Status:** **Accurate**
- **Qt 6.11 Sources:**
  - [Qt Quick Compiler](https://doc.qt.io/qt-6/qtqml-qtquick-compiler-tech.html)
  - [QML Script Compiler](https://doc.qt.io/qt-6/qtqml-qml-script-compiler.html)
  - [QML Type Compiler](https://doc.qt.io/qt-6/qtqml-qml-type-compiler.html)
- **Findings:**
  - `qmlcachegen` is the standard open-source AOT compiler integrated with `qt_add_qml_module()`.
  - `qmltc` compiles QML documents into C++ classes (opt-in via `ENABLE_TYPE_COMPILER`).
  - As requested, commercial-only `qmlsc` can be disregarded for open-source development.
  - In Qt 6.8 / 6.11, CMake target `all_aotstats` is officially supported for viewing AOT metrics.

---

### 2. Rule 1: Always Declare Bound Component Behavior
- **Rule Text:** `pragma ComponentBehavior: Bound` at line 1 of every `.qml` file.
- **Status:** **100% Accurate**
- **Qt 6.11 Sources:**
  - [Structure of a QML Document - ComponentBehavior](https://doc.qt.io/qt-6/qtqml-documents-structure.html#componentbehavior)
- **Findings:**
  - In Qt 6.11, the default is still `Unbound`.
  - Specifying `Bound` guarantees that inner components (e.g., in `ListView`, `Repeater`, `TableView`) do not receive dynamic context objects and can only resolve outer IDs and required properties statically.
  - Qt documentation explicitly states: *"In a future version of Qt the default will change to Bound."*

---

### 3. Rule 2: Eliminate `Qt.rgba()` and Inline JS Color Expressions
- **Rule Text:** Avoid `Qt.rgba()`, `Qt.lighter()`, `Qt.darker()`, `Qt.tint()` in bindings.
- **Status:** **Problem description is correct; QML workaround is invalid**
- **Qt 6.11 Sources:**
  - [QML Script Compiler - Limitations](https://doc.qt.io/qt-6/qtqml-qml-script-compiler.html#limitations-when-compiling-javascript-to-c)
  - [Qt QML Type Reference - Qt Object](https://doc.qt.io/qt-6/qml-qtqml-qt.html)
- **Findings:**
  - `Qt.rgba()`, `Qt.lighter()`, `Qt.darker()`, and `Qt.tint()` return dynamic `QVariant`/`QJSValue` representations through the QML engine's global lookup table. In `qmlcachegen`, bindings calling them produce:
    `codegenResult: 2` (*"Cannot generate efficient code for internal conversion with incompatible or ambiguous types: call to method tint, returning QVariant -> QColor"*).
  - **Issue with Skill's Example:** The skill suggested wrapping `Qt.alpha()` in a QML helper function:
    ```qml
    function withAlpha(c: color, a: real): color {
        return Qt.alpha(c, a); // ERROR: Qt.alpha does not exist in standard QtQuick; still fails AOT!
    }
    ```
  - **Correct Resolution:**
    1. **Static Colors:** Use 8-digit hex strings (`"#80ffffff"`).
    2. **Dynamic Colors:** Expose a C++ utility class / singleton with strongly-typed `Q_INVOKABLE` methods returning `QColor`:
       ```cpp
       // C++ ThemeHelper or ColorUtil (QML_ELEMENT / QML_SINGLETON)
       Q_INVOKABLE QColor withAlpha(const QColor &baseColor, qreal alpha) const {
           QColor c = baseColor;
           c.setAlphaF(std::clamp(alpha, 0.0, 1.0));
           return c;
       }
       ```

### 4. Rule 3: Replace Untyped JS Arrays with `ListModel`, `list<T>`, or `QAbstractListModel`
- **Rule Text:** Avoid `readonly property var items = [...]` as a model.
- **Status:** **Accurate (Expandable to `list<T>`)**
- **Qt 6.11 Sources:**
  - [Type Annotations and Assertions](https://doc.qt.io/qt-6/qtqml-javascript-hostenvironment.html#type-annotations-and-assertions)
  - [QML Object Attributes - List Properties](https://doc.qt.io/qt-6/qtqml-syntax-objectattributes.html#list-properties)
- **Findings:**
  - Untyped `var` arrays force runtime `QJSValue` unpacking.
  - In addition to `ListModel` and C++ `QAbstractListModel`, Qt 6 supports strongly-typed sequence properties:
    ```qml
    property list<string> categories: ["Audio", "Network", "Advanced"]
    ```
    Delegates can bind to `required property string modelData` with 100% native AOT compilation.

---

### 5. Rule 4: Explicitly Type All Delegate Roles and Properties
- **Rule Text:** Every item delegate MUST declare `required property <Type> <roleName>` and `required property int index`.
- **Status:** **100% Accurate**
- **Qt 6.11 Sources:**
  - [Structure of a QML Document - ComponentBehavior](https://doc.qt.io/qt-6/qtqml-documents-structure.html#componentbehavior)
  - [QML Object Attributes - Required Properties](https://doc.qt.io/qt-6/qtqml-syntax-objectattributes.html#required-properties)
- **Findings:**
  - Under `ComponentBehavior: Bound`, delegates do not have context properties (`model.roleName` is prohibited).
  - Strongly typing `required property <Type> <roleName>` allows `qmlcachegen` to perform direct C++ property reads on the delegate object.

---

### 6. Rule 5: Scope Nested Delegate Property Lookups
- **Rule Text:** Inside delegate child items, qualify properties with the delegate `id` (e.g. `barDelegate.index`).
- **Status:** **100% Accurate**
- **Qt 6.11 Sources:**
  - [Structure of a QML Document - ComponentBehavior](https://doc.qt.io/qt-6/qtqml-documents-structure.html#componentbehavior)
- **Findings:**
  - In bound lexical scopes, nested items do not inherit unqualified delegate role names. Referencing `barDelegate.index` avoids scope ambiguity and enables static C++ resolution.

---

### 7. Rule 6: ScrollView and TextArea Child Composition
- **Rule Text:** Do not set `contentItem: TextArea { ... }` on `ScrollView`; declare `TextArea` as a direct child.
- **Status:** **100% Accurate**
- **Qt 6.11 Sources:**
  - [ScrollView QML Type](https://doc.qt.io/qt-6/qml-qtquick-controls-scrollview.html)
  - [TextArea QML Type](https://doc.qt.io/qt-6/qml-qtquick-controls-textarea.html)
- **Findings:**
  - `ScrollView.contentItem` expects a `Flickable`. `TextArea` inherits `Control` (not `Flickable`). Declaring `TextArea` as a child places it properly into the `ScrollView`'s internal flickable content item.

---

### 8. Rule 7: Dialog and Popup Positioning and Palette Access
- **Rule Text:** `Dialog` and `Popup` inherit `Popup` (not `Item`) and live in `Overlay`; do not use `anchors.centerIn: parent`.
- **Status:** **100% Accurate**
- **Qt 6.11 Sources:**
  - [Popup QML Type](https://doc.qt.io/qt-6/qml-qtquick-controls-popup.html)
- **Findings:**
  - `Popup` is a `QQuickPopup` (`QObject`), not a visual `QQuickItem`. It does not have anchor properties on itself for positioning against parent items.

---

### 9. Rule 8: Avoid Inline Dynamic JavaScript in Bindings
- **Rule Text:** Avoid `.trim()`, regex, or untyped JS methods in reactive bindings.
- **Status:** **100% Accurate**
- **Qt 6.11 Sources:**
  - [QML Script Compiler - Limitations](https://doc.qt.io/qt-6/qtqml-qml-script-compiler.html#limitations-when-compiling-javascript-to-c)
- **Findings:**
  - Dynamic JavaScript constructs that cannot be statically mapped to C++ equivalents fall back to byte code.

## Modern Qt 6.5–6.11 Pragmas to Add to Skill

Qt 6.5 through 6.11 introduced several pragmas that directly affect AOT compilation and type safety:

| Pragma | Introduction | Recommended Setting | Purpose / AOT Benefit |
| :--- | :--- | :--- | :--- |
| `pragma ComponentBehavior: Bound` | Qt 6.4 | `Bound` | Guarantees static lexical scope for inner components / delegates. |
| `pragma FunctionSignatureBehavior: Enforced` | Qt 6.5 (default in 6.7+) | `Enforced` (default) | Enforces function parameter/return types, enabling `qmlcachegen` to compile JS functions to C++. |
| `pragma ValueTypeBehavior: Addressable` | Qt 6.6 | `Addressable` | Allows value types (`rect`, `color`, `size`) to be used with `as` and `instanceof`. |
| `pragma ValueTypeBehavior: Assertable` | Qt 6.8 | `Assertable` | Ensures `as` performs strict type checking on value types without unwanted type coercion. |
| `pragma ListPropertyAssignBehavior: ReplaceIfNotDefault` | Qt 6.3 | `ReplaceIfNotDefault` | Clarifies list property assignment behavior when deriving components. |
| `pragma Translator: "<context>"` | Qt 6.7 | Explicit context string | Sets the translation context for `qsTr()`. |

## CMake Built-in Target (`all_aotstats`)

In Qt 6.8+, Qt provides a built-in target to inspect AOT compilation rates:
```bash
cmake --build build --target all_aotstats
```
This is enabled by default via `QT_QML_GENERATE_AOTSTATS=ON`.
